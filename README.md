## Phone test

1. Open https://ideal-mongoose-563.convex.site on the phone. The laptop does not need to be running.
2. Refresh the page. For a local development preview instead, run `npx convex dev --once` and `npm run dev` on the laptop, connect the phone to the laptop's Wi-Fi and open `http://192.168.1.4:5173`.
3. Choose the actual **Reporting date** (for a 7 October DSR, select 7 October 2026). Tap **Add DSR Photos** for the sheet/notebook, then **Add Other Photos** for bills and payment screenshots: JPEG, PNG or WebP, up to six photos, 10 MB combined. HEIC must be exported as JPEG first. Originals are not resized.
4. Tap **Start AI Scanning**. This makes one paid AI call for the selected photos. There are no automatic retries.
5. Check the selected reporting date and the actual date read from each document and each photo's classified type, own date, exact labels and ₹ amounts. Unreadable amounts say **Not extracted**; tentative figures have `?`. An explicitly read zero is **₹0**.
6. Read **Compare with the DSR** and **Where expense money went**. Source photos are available beside each check. Expense bills and their payments are not added together: a bill is counted once and its linked cash/online payments are shown separately. A missing bill stays flagged even if amounts agree.
7. Under **Connections to check**, expand the relevant entry. If you know it, add its role, payee, purpose and payment method; choose the bill or other expense payment it belongs with, then tap **Use this context**. This makes no new AI call. Your context is labelled separately and never changes the original amount or raw AI reply. Unreadable amounts require a clearer photo; missing or different dates remain excluded.
8. For a monthly table, the selected date identifies the row. If the row cannot be read or the DSR shows another date, the app leaves DSR amounts unextracted. Check your selected date or upload a clearer photo. Missing dates on individual photos still say **Date not extracted**; bills with another date are flagged.
9. On failure, photos stay selected; tap **Retry Scanning**. **Add DSR Photos** and **Add Other Photos** append photos in the appropriate area. **Remove photo** removes a selection and clears old readings. Expand **View raw AI response** to inspect the latest provider response.

## Extraction and limits

A Convex HTTP action calls the OpenAI Responses API with `gpt-6-luna`, low reasoning, `max_output_tokens: 6000` for contextual comparison (legacy extraction remains 1500), and `store: false`. `OPENAI_API_KEY` is in backend Convex environment variables, never frontend code or a VITE variable. The public endpoint is configured with `VITE_CONVEX_SITE_URL`. At most 100 attempted AI calls per rolling hour across the app, enforced atomically before the chargeable call. Provider failures consume their reserved slot. Rate-limit or provider failure says **Busy right now. Try again in a few minutes.**

The current photo request is `{mode:"compare", date, dsrSources, images:[...]}`. The original dated reading path remains available for older open pages. Source numbers are assigned by code from each upload area. AI returns `{date,documents:[{source,kind,date,lines:[{section,label,amount,unclear}]}],contexts:[{source,line,role,party,purpose,billRef,transactionRef,method,unclear}]}`. Each context points at one original line; it contains no calculated amount. Roles distinguish charges, incoming/outgoing payments, advances, refunds, written totals and balances. Context reading is still AI-extracted and must be checked. Root date must equal the selected reporting date. DSR-designated sources may be Daily sheet, Handwritten DSR or Not identified; Other sources cannot become the main DSR. Read only the selected date's sheet row. A DSR source with a different or unreadable date cannot supply numeric DSR lines. Every numbered input needs exactly one valid result; missing, duplicate or invented source numbers are rejected. Each supporting photo keeps its own visible date or null; different-date records are flagged. Missing date or missing DSR selection blocks scanning before any paid call. Changing the selected date or any selected photo clears old results.

The screen validates and renders the latest raw response, ignoring independent extracted objects, dates or supplied totals. Bills never fill blank DSR cells. Original figures remain grouped within each photo. Convex separately calculates comparison totals using integer paise, then the page verifies those results against the same latest raw response. It never substitutes independent simulated totals. Only handwritten DSR section totals use the existing integer-paise calculation: explicit Total labels are excluded, uncertainty makes totals incomplete, and readable subtotals remain separate. Daily-sheet columns and written summary totals are displayed individually to avoid counting a total and its components twice.

Photos and unconfirmed readings remain in the current browser session; the extraction action sends the images to Convex and OpenAI but does not save or log them. Refresh clears the current selection and draft. Confirm day saves only the structured reading, original AI answer text, corrections, written totals, calculated checks and confirmation time. `store:false` disables Responses storage, not all provider processing retention. Earlier separately uploaded supporting originals remain preserved in development Convex storage and metadata, with no public file-read/list route. Legacy automatic-date/Excel API paths remain for previously opened clients; the current page does not offer them. Financial approval remains a later milestone.

## Correct, confirm and reopen on dev

Each extracted line has Correct and View original. Save Correction validates the label/amount and rechecks in Convex without another AI call; Cancel keeps the old value. History is private to the signed-in account. Convex Auth verifies the session on every scan, correction/check, confirmation and History read. Signing out clears the current browser draft and hides the manager app. Sign in to the same account to reopen its History on another browser. Legacy browser-scoped days remain preserved on dev, separate from account-owned records; they are not assigned to new users or deleted. No migration is included. Dev and production have separate accounts, keys and records; production is unchanged. Photos are never part of a confirmed day.

## Context and comparison rules

The AI reads roles, names, purpose, dates and references; code establishes connections and calculates. A payment links automatically to a unique same-day expense bill with the same payee and either the same bill reference or the same visible purpose. Amount equality alone never establishes a match. Clearly identified payments with the same payee and purpose/reference can form one payment-only expense; it remains **Missing expense bill**. Ambiguous connections need your explicit choice. An explanation is context, not proof that a bill exists or cash was counted.

Repeated explicit bill/transaction references count once; conflicting copies or possible duplicates without identifying references leave comparisons incomplete. Overlapping DSR photos cannot produce a complete match. Guest cash and UPI are compared separately; advances/refunds are displayed separately. A context answer may classify or link an existing line, but cannot change its amount/date/source or turn a repeated written total into another transaction. The comparison endpoint uses the current raw reading plus your answers, validates them again and performs no provider call, storage write or quota mutation. Answers are temporary and reset for new photos, a new date or a fresh scan.

The comparison response schema restricts DSR classifications by upload source and uses the documented nested `anyOf` form from the [OpenAI Structured Outputs guide](https://developers.openai.com/api/docs/guides/structured-outputs). No paid real-photo test has been run for this new schema/instruction set; simulated checks prove calculations and the browser flow, not OCR accuracy. There are no automatic AI retries. The larger response cap permits longer replies and can increase scan cost; no production cap/cost has been verified.

## Home and History design (dev only)

The home page keeps the same date, DSR/Other photo inputs and scanning action in clearer panels. History shows one card per confirmed date with five saved DSR figures: Room revenue, Food revenue, Guest cash, Guest UPI and Expenses. Cards read the persisted DSR side of saved checks, including manager corrections; they never substitute supporting amounts or calculate a new report. Missing or uncertain DSR totals stay Not extracted. Open the date for the existing saved lines, original/corrected values, written totals and checks. Amount reads are bounded to the existing 20-date page and reject mismatched saved versions. Loading failures offer Retry amounts. Small fades and saved-day transitions are disabled when reduced motion is requested. Screenshots and test records use fabricated data; no paid scan is needed to verify the redesign. Production is unchanged.

Home numbers the Reporting date, DSR photos and Other photos steps and shows compact original-photo thumbnails. Last confirmed shows the document date of the account's most recent confirmation, including when an older day was confirmed later. Displayed dates use 10 Oct 2026; stored dates remain unchanged. History groups dates by month and shows grey Not enough info for missing/incomplete saved checks, amber Check for complete checks with a difference, or green Matches when all six saved checks match. These statuses describe saved checks, not financial approval.
